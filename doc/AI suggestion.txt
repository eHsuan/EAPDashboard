2. 設備狀態變更上報 (對應 MQTT 2.6 Status Change Report)
機台燈號或狀態（RUN、IDLE、DOWN 等）改變時，將變化上報給系統。
所需的 SECS SF：
S6F11 (Event Report Send)
S6F12 (Event Report Acknowledge)
目前 EAP 狀況：已實作接收 CEID="50,51,52,53" 與對應的變數 VID 102。

3. 警報上報 (對應 MQTT 2.4 Alarm Report)
發生硬體或軟體異常時，即時通報。
所需的 SECS SF：
S5F1 (Alarm Report Send)
S5F2 (Alarm Report Acknowledge)
目前 EAP 狀況：已實作接收與轉譯 ALCD、ALTX。
✅ 滿足現況，但需注意：
需確保 EAP 將 S5F1 轉譯為 MQTT 的 AlarmStatus (Start/End)、AlarmCode 與 AlarmMsg。
4. 製程資料收集 (對應 MQTT 2.5 Process Data Report)
機台完成一個生產單位（Unit）時，上報該單位的品質與製程參數（EDC）。
所需的 SECS SF：
S6F11 (Event Report Send)
S6F12 (Event Report Acknowledge)
目前 EAP 狀況：目前僅實作 Track In/Out (CEID 200, 206) 及狀態變更。
⚠️ 需要擴充實作：
針對舊機台的「Unit 完成事件 (Unit Complete CEID)」，EAP 需新增對該 CEID 的解析。
需從對應的 S6F11 中抽出製程數據 VIDs（如溫度、壓力等），將其打包成 MQTT 規範的 ProcessData JSON 陣列。
5. 追蹤資料 (對應 MQTT 2.14 Trace Data Report)
固定頻率（如每幾秒）連續上報機台感測器數據（如溫度、電壓曲線）。
所需的 SECS SF：
S2F23 (Trace Initialize Send) - EAP 主動發起
S2F24 (Trace Initialize Acknowledge) - 設備回覆
S6F1 (Trace Data Send) - 設備主動上報
S6F2 (Trace Data Acknowledge) - EAP 回覆
目前 EAP 狀況：完全未實作。
🚨 必須新增實作：
EAP 收到 MQTT 的 InitTraceData 時，需轉換為 S2F23 下發給設備（設定 TRID、DSPER 採樣頻率、TOTS 總採樣數以及所需追蹤的 SVIDs）。
EAP 需實作接收 S6F1，並將收集到的資料轉譯為 MQTT RtnTraceData (包含 CycleTime, Parameter 陣列等)。
6. 設備狀態查詢 (對應 MQTT 2.9 Status Request)
當 EAP 重啟或斷線重連時，EAP 需主動向機台要當前的狀態與參數。
所需的 SECS SF：
S1F3 (Selected Equipment Status Request)
S1F4 (Selected Equipment Status Data)

確保系統與機台時間一致。
所需的 SECS SF：
S2F31 (Date and Time Set Request)
S2F32 (Date and Time Set Acknowledge)
